# 为什么 AI 证明打不到工程现场？——114 道工程数学问题与一场公开的可信度审计

*AI 定理证明在纯数学里一路狂奔，工程师却没法把手里的控制系统扔给 AI 问一句"它安全吗"——因为那条工程约束，从没被写成一个精确的数学命题。缺口不在证明，在陈述。*

MathX 是一个小型、开放、非商业的项目，专门补这个缺口。它把自然科学与工程里的判定需求，翻译成可核验、可被工程消费的数学命题，并记录"要信这条判定，得先信哪些上游证书"。这篇文章是它的现状快照——包括我们刚做完的一次诚实的可信度审计：**114 道题，只有通过审计的才展示。**

## 一、114 道题，每道都是一个"可攻击的命题"

MathX 目录里每一条都是跨学科的开放问题，且陈述方式保证"被公认的答案有精确定义"。当前规模：

| 维度 | 数量 |
|---|---|
| 问题总数 | **114** |
| 数学物理 | 35 |
| 数学化学 | 24 |
| 数学工程 | 30 |
| 数学生物 | 25 |
| 开放（open） | 101 |
| 部分解决（partial） | 13 |
| 完全解决 | 0 |
| 跨题关系边 | 109 |
| 平均障碍记录 / 题 | 1.8 |

两道题的"质地"能说明问题。**mp-001**（硬球系统全时段的 Boltzmann–Grad 极限）仍开放，真实困难被如实记录：*平均自由程之后的 recollision control*、*缺 uniform-in-time 先验界*。**mp-011**（Almost Mathieu 算子的 Dry Ten Martini 问题）部分解决——2023 年非临界情形被攻下，临界耦合与 Liouville 情形仍然开放。这些不是编造的条目，是真实的研究前沿，而且被陈述到可以直接开打的程度。

## 二、可信度是第一公民：一场逐题审计

AI 生成内容最大的风险是"表面精确、实质存疑"。2026-08 一次性起草的 114 条，我们不能假装它们是专家写出来的。所以我们做了一件事：**把可信度做成第一公民字段，并且刚刚完成了一次逐题审计。**

### 1. 来源三态，不再自盖章"已验证"

| 来源状态 | 数量 |
|---|---|
| AI 初稿（AI-drafted） | 104 |
| Lean 可编译（lean-compilable，可编译的 Lean 4 形式化陈述） | 10 |
| 专家复核（expert-reviewed） | 0 |

没有"Verified"印章。自己盖的章不叫验证。我们只信机器——机器目前为 10/114 道题签发了可编译的 Lean 陈述。这个数字就是"今天有多少条目是机器为真的"的诚实度量，也正是我们留给社区去增长的清单。

### 2. 逐题审计展示门：5 处问题全部修复，114 条全部通过

2026-09-02，我们对全部 114 条执行了 5 维一致性审计（陈述精确性 / 收录标准 / 状态时效 / 文献支撑 / 评级合理）。**只有通过审计的条目才在公共站点展示；未通过的不删除，原因公开在审计表里，供人复核升级。**

首轮审计揪出 **5 条问题**。它们没有一条被静默删除——而是逐条修复、逐条核实，然后全部恢复展示。这正是审计该有的样子：**宁可撤下，不靠嘴硬；修好了，再放回来。**

| ID | 审计发现 | 修复（已核实） |
|---|---|---|
| me-020 | 引文作者名单乱码、DOI 误挂到一篇无关的心理学论文 | 更正为 Gérard-Varet–Dormy (JAMS 23, 2010) 与 Grenier–Guo–Nguyen (Duke Math. J. 165, 2016) |
| mp-028 | 状态标 open 与所引文献矛盾 | 改为 partial：Deng–Hani (Invent. Math. 233, 2023) 已证 O(1) 动力学时标的波动能方程推导；长时标/非高斯仍开 |
| mp-030 | 状态标 open 过时 | 改为 partial：Imbrie (J. Stat. Phys. 163, 2016) 已证强无序下 MBL；无条件热力学极限稳定性仍争 |
| me-017 | 状态标 open 过时 | 改为 partial：Haberman–Tataru (Duke Math. J. 162, 2013) 已证 Lipschitz 情形；$L^\infty$ 情形仍开 |
| mp-035 | 判定路径标 experimental 违反收录标准 | 改为 analytical：目标是严格证明，实验观测（超流薄膜普适跃变）仅为佐证，不是验证方法 |

现在 **114 条全部通过审计、全部恢复展示**。审计的价值不是"把可疑条目关进小黑屋"，而是把每一条可疑都变成一次公开可查的修复。

## 三、协议账本：追加式、可哈希校验、可独立核验的信任层

站点上的一切声明（带证收窄、形式化状态变更）都进入协议账本（契约 v0.1），三条性质：

- **只追加**：历史永不改写。
- **哈希校验**：每条携带证据哈希，篡改证据即破坏一致性，审计即时报错。
- **参考核验器**：一个只读核验器独立于提交/审核路径，逐条检查带证区间（是否机器可解析？是否空洞？是否越过信息门限？）。

写入路径已开放，提交 → 审核 → 入账 → 审计全链路在生产运行。账本当前刻意为空——我们宁愿交付一本诚实的空账本，也不伪造第一条记录。

## 四、从"问题层"到"解题层"：需求侧倒查

MathX 不只是问题收录集。我们还做了需求侧的倒查：**工程反向需求清单**——从具体工程需求出发，反查支撑它的问题、经验定律和就绪度（served / partial / gap）。

当前 **18 条需求**覆盖热工程、CFD、控制、生物反应器、成像、材料、量子计量等 **17 个工程领域**，**1 条 served、10 条 partial、7 条 gap**。每条需求是一份"判定档案"：按依赖顺序列出要 certify 的判定链（可消费证书 / 奠基结构证 / 经验定律）、对接的工程标准（JEDEC、ISO 26262、IEC 61511、ASME V&V 等）、什么算被服务、当前障碍与工作流落点。举一例：*"对流冷却的可认证热裕量"*——两道目录问题提供带证区间（partial），但 Fourier 定律从微观动力学的推导残差仍然开放。缺口被陈述出来，于是可以被攻击，而不是被一笔带过。每道问题页还会反查"被哪些工程需求倒查"，把需求侧和问题层连成闭环。

配套的**经验定律形式化边界图谱**：6 条工程常用经验定律，3 条 partial（如 Fourier 定律：宏观陈述广泛使用，但从微观动力学严格推导是开放残差）、3 条 gap（如生物过程工程里的 Monod 定律、湍流里的混合长度假设，连严格形式化陈述都没有）。每条 gap 都是一个"证明者需求"：一个被精确陈述、等着被形式化或给出误差界的目标。

## 五、机器层：给 AI 基准的下游接口

所有数据都以稳定、带版本、带 ETag 的接口对外：

- `problems.json` — 114 道已通过审计的问题（含证书、障碍、关系）
- `needs.json` — 10 条工程需求倒查
- `laws.json` — 经验定律边界图谱
- `ledger.json` — 只追加协议账本
- `impact.json` — 影响域实证链（全部挂接真实 arXiv 文献）
- `benchmark.json` — 判定可消费的子集

AI 证明器、下游工具可以直接订阅。这不是宣传词——是交付物。

## 六、我们在找什么

MathX 是公共事业、志愿者运营，不接商业单。对你有价值的事，按优先级排：

1. **认领一个证明任务** —— 5 条 gap 需求、3 条 gap 定律都是被精确陈述的目标。形式化一条，或给出一条误差界。
2. **复核一条陈述** —— 104 条 AI 初稿需要专家眼睛，才能从 AI-drafted 升级到 expert-reviewed。
3. **消费机器层** —— `problems.json` / `needs.json` / `ledger.json` 就是为 AI 证明器准备的。
4. **复核审计** —— 审计发现的 5 处问题已全部修复核实，但这不代表审计就此结束：任何新的"状态过时 / 引文存疑 / 路径违规"都欢迎你来指出，复核通过即升级，复核不通过即撤下。

边界从来不是"AI 能不能证"，而是"有没有人把它精确陈述到可以开打"。这才是 MathX 做的事。
